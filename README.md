# 健身房会员办卡订单管理模块

前端工程师笔试项目，按阶段开发、验收和提交 Git。
当前仅完成项目初始化；业务功能尚未实现，不能作为完整答卷提交。

## 技术栈

React 18、Vite、React Router 7、Ant Design 5、axios、zustand、dayjs。
语言使用 JavaScript / JSX，样式使用普通 CSS；ESLint 检查代码，Prettier 格式化。
主版本由 package.json 约束，具体安装版本由 package-lock.json 锁定。

## 启动步骤

开发环境：Node.js 22.16.0、npm 10.9.2。

```sh
npm ci
npm run dev
```

打开终端打印的地址，默认 http://localhost:5173；端口被占用时，以终端显示为准。

```sh
npm run lint
npm run format:check
npm run build
npm run preview
```

`npm run format` 自动格式化，`npm run lint:fix` 修复可自动处理的问题。
Windows PowerShell 若提示 npm.ps1 执行策略错误，可将 npm 替换为 npm.cmd。

## 请求层与状态管理设计（待实现）

所有业务请求经过 axios 实例，baseURL 读取 VITE_API_BASE_URL；请求拦截器读取最新
token 并注入 Authorization。响应拦截器统一提示错误，401 清除登录态并返回登录页。

模拟接口维护模块级内存数据，至少 30 条订单覆盖六种状态。查询支持筛选、排序和分页；
新建、续卡、撤单修改同一份数据，刷新浏览器后允许重置。拟通过 axios-mock-adapter
接入，确保页面不绕过请求层。具体实现文件在后续阶段补充。

zustand 管理登录用户、token 及登录/退出动作；列表查询和弹窗状态由页面和自定义 hook
管理。localStorage 持久化 token 和用户名，初始化时恢复登录态。

## 需求理解与实现约定（后续按此实现）

1. “创建时间升序”与“最新订单在最前面”矛盾，以最新优先为准，采用降序。
2. 待审核、待制卡、待寄卡、已完成、已到期、已取消共六种状态。
3. 新建费用不打折；单次续卡 5 年及以上打八折，批量时展示每笔费用和合计费用。
4. 0 元展示 0.00；null、undefined、空字符串表示缺失，展示 —。
5. 任意选中订单非已到期则阻止整批续卡，并列出不符合条件的订单号。
6. 撤单仅允许待制卡、待寄卡，确认框列出实际操作的订单号。
7. 续卡购卡年限累加，累计年限可超过 10 年；1～10 的限制用于每次购买/续卡输入。
8. 暂定订单金额为累计办卡费用，续卡后累加本次费用。历史金额缺失时保持缺失，
   避免把未知金额当零；此口径需业务确认，不能代替实际收款流水。
9. 手机号暂按中国大陆手机号校验；姓名去除首尾空格后校验 2～30 个字符。
10. 操作成功重新查询；新建成功返回列表使用全部 Tab、空搜索条件和第 1 页。
11. 不额外实现审核、制卡、寄卡状态推进按钮。

## Part 5：导出功能澄清问题

1. 导出当前页、全部筛选结果，还是勾选数据？
2. 哪些状态允许导出？禁止状态及理由是什么？
3. 是否按用户角色控制权限？需要模拟财务角色吗？
4. 导出哪些字段，是否包含手机号和备注？
5. 金额表示累计费用、实际收款还是本次交易？续卡如何对账？
6. 金额需要千分位、两位小数和货币符号吗？零元与缺失如何展示？
7. 混入禁止状态时，阻止整批还是跳过并提示？
8. 使用什么软件打开 CSV？要求 Excel 打开中文不乱码吗？
9. 时间采用哪个时区和格式，导出顺序是什么？
10. 是否限制数量，是否需要导出审计记录？

## Part 5：导出实现假设（待实现）

1. 无勾选时导出当前 Tab、搜索条件下全部匹配结果，包含所有分页。
2. 有勾选时导出全部勾选记录，含跨页记录；界面明确显示导出范围。
3. 仅已完成、已到期允许导出，以已结束的办卡流程作为本次对账范围。
4. 只要包含禁止状态就阻止整批并列出订单号，不静默跳过。
5. 不额外增加角色系统，所有模拟登录用户遵循相同规则。前端规则仅用于笔试演示，
   真实系统由后端授权和过滤数据。
6. 导出订单号、会员姓名、购卡年限、订单金额、状态、创建时间，不含手机号和备注。
7. 金额单位为元，千分位、两位小数、不加货币符号；0 显示 0.00，缺失为空字段。
8. 时间按 Asia/Shanghai 展示为 YYYY-MM-DD HH:mm:ss，创建时间降序排列。
9. UTF-8 编码加 BOM，CRLF 换行，正确转义逗号、双引号、换行。
10. 对可能被表格软件解释为公式的文本进行防护；CSV 千分位金额可能被识别为文本，
    财务需要数值运算时另行确认格式。
11. 空数据提示，不下载空文件；文件名包含导出时间。本题暂不增加数量限制和审计。

## 最难的问题与解决过程

当前阶段遇到的问题是新 Vite 模板默认 React 19 和 Oxlint，与题目不一致。
检查生成的依赖后，限定 React 18 / Router 7 / antd 5，替换为 ESLint，增加 Prettier
与冲突规则配置，通过安装版本和检查命令验证。业务阶段的难点在完成对应功能后补充。
