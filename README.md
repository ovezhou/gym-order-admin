# 健身房会员办卡订单管理模块

前端工程师笔试项目，按阶段开发、验收和提交 Git。
当前已完成初始化、登录、后台布局、请求层、可写模拟接口、列表、新建、续卡、撤单和 CSV 导出。
已支持跨页勾选和自定义查询 hook；最终综合验收、公开仓库和提交材料仍待完成。

## 技术栈

React 18、Vite、React Router 7、Ant Design 5、axios、zustand、dayjs。
语言使用 JavaScript / JSX，样式使用普通 CSS；ESLint 检查代码，Prettier 格式化。
主版本由 package.json 约束，具体安装版本由 package-lock.json 锁定。

## 启动步骤

开发环境：Node.js 22.16.0、npm 10.9.2。

```sh
npm ci
npm run dev
```

打开终端打印的地址，默认 http://localhost:5173；端口被占用时，以终端显示为准。

```sh
npm run lint
npm run format:check
npm test
npm run build
npm run preview
```

`npm run format` 自动格式化，`npm run lint:fix` 修复可自动处理的问题。
Windows PowerShell 若提示 npm.ps1 执行策略错误，可将 npm 替换为 npm.cmd。

## 请求层与状态管理设计

已实现：`src/services/http.js` 创建统一 axios 实例，baseURL 读取 VITE_API_BASE_URL，
缺省为 /api；超时 15 秒。请求拦截器每次获取 zustand 最新 token，注入
Authorization: Bearer <token>，未登录时删除旧请求头。
响应拦截器返回 response.data，统一处理业务错误、网络异常及超时，同时保持 Promise 拒绝，
供页面停止加载、保留表单等。主动取消的查询不弹出错误。

401 会清除 zustand 和 localStorage 登录态，发出 unauthorized 事件。
`HttpFeedbackBridge` 在 antd App 和 BrowserRouter 内订阅事件，显示中文错误，
用 navigate replace 返回 /login 并记住原路径。并发 401 只处理一次；
重新登录后恢复处理能力。旧会话的迟到 401 不清除新会话。
请求工厂可注入 token、提示及退出动作，让自动测试验证真实拦截器而不依赖 React 渲染。

`src/mocks/installMockApi.js` 用 axios-mock-adapter 拦截同一个实例，浏览器与 Node
均可运行。开发及生产预览都启用模拟接口，默认延迟 250ms，无需独立后端。
`orderDatabase.js` 闭包维护一份内存数据；36 条初始订单覆盖六种状态，每种 6 条，
包含零元、null、缺少金额字段、空字符串等边界数据。新建、续卡、撤单修改这份数据，
随后查询返回变更；刷新或开发热更新重新初始化数据。退出不会主动重置订单。

模拟接口验证 token 的 mock 格式，仅供本题演示；不构成真实鉴权。
批量写入先检查全部 ID 和状态再统一修改，无部分成功；重复 ID 去重，避免重复收费。
返回副本，避免页面直接改写数据库。费用由接口计算，不信任前端提交的金额或状态。

已实现：`src/stores/authStore.js` 的 zustand store 管理用户名、token 以及 login/logout。
`gym-order-session` 是 localStorage 的唯一登录键，仅保存 mock token 和用户名，不保存密码。
初始化同步读取并校验存储，再让路由守卫判断登录，避免刷新时先跳登录再恢复的闪烁。
登录先写存储再更新状态，存储失败则提示并维持未登录；退出删除保存的信息并清空内存状态。
损坏或不完整的存储会清理并退回未登录，不导致白屏。

`RequireAuth` 使用 Outlet 保护 /、/orders、/orders/new，未登录以 replace 跳到 /login，
保存原目标。登录后只允许返回已知后台路由，避免任意外部跳转；直接登录默认进入 /orders。
登录用户再访问 /login 会进入订单列表。未知地址始终显示独立 404 页。
后台布局依据当前 pathname 更新菜单选中项及面包屑。页面通过 React.lazy 和 Suspense 按需加载。
提示使用 antd App.useApp，确保继承主题和中文配置。

列表通过 `useOrders` 自定义 hook 管理，查询参数、分页、加载、错误和结果保存在页面内，
无需跨页面共享的状态不放进 zustand。Tab、搜索和每页条数变化重置为第 1 页；
重置清空搜索并保留当前 Tab，每次查询开始清除旧结果，失败显示重试入口。
查询 effect 使用 AbortController 取消上次请求，清理时标记失效；reducer 额外校验
响应对应的查询对象，避免旧请求在 effect 清理之前返回并覆盖新结果。
数据减少导致页码越界时，自动回到最后一页重新查询。
搜索输入是待提交的草稿，点击查询或回车后生效；切换 Tab 保留已提交的搜索条件。

选择记录以 ID 数组保存在列表页面，Table 使用受控 selectedRowKeys 与
preserveSelectedRowKeys，支持翻页、切换 Tab、搜索与刷新查询后保留勾选。
表头全选只选择当前页；界面显示包含其他页与筛选的选中总数，并提供清空选择。
离开列表后不保留选择，整页刷新也不保存选择到 localStorage。

`useOrderActions` 管理操作预检、弹窗、提交和错误；行内与批量调用同一套逻辑。
预检仅传 ID，通过 lookup 获取最新状态，验证整批资格并列出全部非法订单号；
确认弹窗绑定预检得到的订单快照，不受后续勾选变化影响。确认提交时模拟接口再次
检查全部 ID 和当前状态，通过后才统一写入。资格规则在领域层共用，避免前后端模拟规则漂移。
续卡弹窗用 useWatch 和共用计价函数展示每笔、合计与八折提示；每次打开是全新表单。
撤单必须通过列出订单号的确认框。提交期间禁用操作和弹窗关闭，同步 ref 防止重复请求。
成功后仅清除已处理订单的勾选，保留无关选择，并重新查询当前 Tab、搜索和页码；
结果数量减少导致页码越界时，由列表 hook 校正到最后一页。失败保留弹窗与输入以便重试。
离开页面时取消预检查询；已发出的写请求由接口完成，返回后不更新已离开的页面。

新建表单使用 antd Form 管理字段和错误，通过 `Form.useWatch` 订阅购卡年限，
调用领域层 `calculateCardFee` 实时计算只读费用。`domain/newOrder.js` 的校验和
规范化函数同时用于页面与模拟接口，统一字符计数、去除首尾空格和字段规则。
提交仅发送四个输入字段，金额、状态和订单号由模拟接口确定。
提交期间禁用表单，另用同步 ref 防止重复提交；页面离开后不再跳转或更新表单。
错误提示由请求层统一显示，页面保留填写内容并展示错误，接口字段错误回填到对应字段。
成功后提示订单号并 replace 返回列表；列表重新挂载，恢复全部 Tab、空搜索和第 1 页，
按创建时间降序展示新订单。

导出由 `useOrderExport` 管理加载、取消查询、错误弹窗及文件生成回执。
有勾选时通过 lookup 查询全部已选 ID 的最新数据；无勾选时通过 all 查询已提交的
Tab 和搜索条件，移除分页参数。服务层统一确定范围，领域层校验整批状态，
工具层将数据生成 CSV；没有专用后端导出接口，文件由浏览器 Blob 和下载链接生成。
导出过程中冻结筛选、勾选和订单操作，同步 ref 防止重复请求；离开页面取消查询。
成功后保留勾选，回执固定显示该文件的范围和数量；失败不生成文件。
临时链接用完移除，延迟释放 Object URL，避免长期占用内存。

## 模拟接口约定

以下路径相对于 baseURL；调用 `src/api/orders.js` 时直接获得数据对象，无需再读取 `.data`。

| 方法 | 路径           | 参数或请求体                             | 返回                          |
| ---- | -------------- | ---------------------------------------- | ----------------------------- |
| GET  | /orders        | tab、orderNo、memberName、page、pageSize | items、total、page、pageSize  |
| GET  | /orders/all    | tab、orderNo、memberName，忽略分页       | items、total                  |
| POST | /orders/lookup | ids 数组                                 | items，包含各页记录的最新数据 |
| POST | /orders        | memberName、phone、years、remark         | 新订单，HTTP 201              |
| POST | /orders/renew  | ids、years                               | items、feePerOrder、totalFee  |
| POST | /orders/cancel | ids                                      | items                         |

tab 为 all / in_progress / expired / completed / cancelled。订单号精确匹配，
姓名去首尾空格后模糊匹配，筛选组合生效；默认 page=1、pageSize=10，单页最多 100 条。
所有列表按创建时间降序；时间相同按订单号降序稳定排序。空查询返回空数组和 total=0。

订单字段为 id、orderNo、memberName、phone、years、amount、status、createdAt、remark。
金额单位为元，createdAt 是 ISO 时间字符串。写操作用 id 定位记录，orderNo 用于展示与搜索。
续卡单次输入 1～10 的整数，购卡累计年限可超过 10；创建时间保持不变。
无效参数返回 400，未登录 401，订单不存在 404，状态冲突 409；错误体包含 message，
必要时附带 fields、missingIds、invalidOrderNumbers，供表单和操作弹窗使用。

## 需求理解与实现约定

1. “创建时间升序”与“最新订单在最前面”矛盾，以最新优先为准，采用降序。
2. 待审核、待制卡、待寄卡、已完成、已到期、已取消共六种状态。
3. 新建费用不打折；单次续卡 5 年及以上打八折，批量时展示每笔费用和合计费用。
4. 0 元展示 0.00；null、undefined、空字符串表示缺失，展示 —。
5. 任意选中订单非已到期则阻止整批续卡，并列出不符合条件的订单号。
6. 撤单仅允许待制卡、待寄卡，确认框列出实际操作的订单号。
7. 续卡购卡年限累加，累计年限可超过 10 年；1～10 的限制用于每次购买/续卡输入。
8. 暂定订单金额为累计办卡费用，续卡后累加本次费用。历史金额缺失时保持缺失，
   避免把未知金额当零；此口径需业务确认，不能代替实际收款流水。
9. 手机号暂按中国大陆手机号校验；姓名去除首尾空格后校验 2～30 个字符。
10. 操作成功重新查询；新建成功返回列表使用全部 Tab、空搜索条件和第 1 页。
11. 不额外实现审核、制卡、寄卡状态推进按钮。
12. 批量撤单也采用整批校验：包含不可撤记录时阻止整批，列出订单号，不静默跳过。
13. 姓名、备注按 Unicode 码点计数，避免扩展汉字和 emoji 被当作两个字符；
    姓名、手机号去除首尾空格，备注保留原内容。输入可超长，但校验失败时不能提交。
14. 勾选跨页及跨筛选保留，批量操作作用于全部已勾选记录，不局限于当前页；
    行内操作只作用于该行，成功时保留其他记录的勾选。

## 已实现的加分项

- 跨页保留勾选：ID 作为稳定标识，操作前查询最新记录，避免只处理当前页或使用缓存状态。
- 自定义 hook：useOrders 抽象查询与请求竞争处理，useOrderActions 统一单笔及批量交互，
  useOrderExport 管理导出查询及反馈。
- 自动测试：覆盖批量原子性、预检后状态变化、金额与年限边界、登录会话和请求异常。
- 提交期间阻止重复请求，页面离开后的异步结果不更新旧页面。

## Part 5：导出实现假设（已实现）

1. 无勾选时导出当前 Tab、已提交搜索条件下全部匹配结果，包含所有分页；
   搜索框里未点击查询的草稿不参与导出。
2. 有勾选时导出全部勾选记录，含跨页记录；界面明确显示导出范围。
3. 仅已完成、已到期允许导出，以已结束的办卡流程作为本次对账范围。
4. 只要包含禁止状态就阻止整批并列出订单号，不静默跳过。
5. 不额外增加角色系统，所有模拟登录用户遵循相同规则。前端规则仅用于笔试演示，
   真实系统由后端授权和过滤数据。
6. 导出订单号、会员姓名、购卡年限、订单金额、状态、创建时间，不含手机号和备注。
7. 金额单位为元，千分位、两位小数、不加货币符号；0 显示 0.00，缺失为空字段。
8. 时间按 Asia/Shanghai 展示为 YYYY-MM-DD HH:mm:ss，创建时间降序排列。
9. UTF-8 编码加 BOM，CRLF 换行，正确转义逗号、双引号、换行。
10. 对可能被表格软件解释为公式的文本添加单引号前缀，覆盖 =、+、-、@、
    相应全角符号、前导空白及制表符/换行；数值金额由格式化工具输出，保留负号。
    CSV 千分位金额可能被识别为文本，财务需要数值运算时另行确认格式。
11. 空数据提示，不下载空文件；文件名包含导出时间。本题暂不增加数量限制和审计。

## 最难的问题与解决过程

当前阶段遇到的问题是新 Vite 模板默认 React 19 和 Oxlint，与题目不一致。
检查生成的依赖后，限定 React 18 / Router 7 / antd 5，替换为 ESLint，增加 Prettier
与冲突规则配置，通过安装版本和检查命令验证。业务阶段的难点在完成对应功能后补充。

阶段 2 的关键问题是刷新恢复登录与路由判断的时序。若仅在页面 effect 中恢复 token，
守卫可能先认定未登录并跳转。解决方式是在创建 store 时同步恢复，守卫订阅最新 token；
结合真实浏览器刷新验证，以及正常、损坏、写入失败和退出后恢复的自动测试。

阶段 3 的难点是批量状态校验与写入一致性。若一边遍历一边修改，后面的订单不合法时，
前面的订单已被更新。解决方式是先去重、查找全部订单、校验状态，再同步执行全部修改。
通过混合状态、缺失 ID、重复 ID 和再次查询的测试证明失败不写入、成功不重复收费。
请求层还处理旧会话的迟到 401，以免新登录被先前请求清除。

阶段 4 的难点是快速切换筛选时，请求返回顺序可能与发出顺序不同。
仅靠请求取消仍不足以覆盖取消前已完成的回调，因此同时使用 effect 失效标记和
reducer 查询对象校验，只接受当前查询的结果与错误。自动测试让旧查询在切换 Tab
和刷新后返回，证明不会覆盖当前查询；浏览器验证连续切换后显示最后选择的状态。
金额格式化显式区分 0 与空值，避免使用 `amount || '—'` 把零元误判为缺失。

阶段 5 实际遇到的问题是 InputNumber 的显示值与表单有效值可能不一致：
设置 min/max 后，键入超范围年限可能仍保留上次有效数值，失焦还可能自动修正。
为了避免按另一年限创建订单，移除输入框的 min/max 自动约束，关闭失焦自动更新，
由共用规则显式校验 1～10 的整数。无效年限费用显示 —，提交被阻止。
浏览器先输入有效的 5 年，再输入 11 年并提交，确认保留 11 年、显示错误且未创建订单，
然后修正为 5 年，确认费用为 6,000.00，成功后列表仅增加一条订单。

阶段 6 的难点是跨页勾选与操作时状态一致性：表格当前页只有部分记录，
保留的旧行对象也可能已经过期。因此只保存 ID，操作前统一 lookup 最新数据，
并在提交接口再校验一次。测试在续卡预检后先修改其中一笔订单，再确认原批次，
证明会返回冲突、列出订单号且不修改其他订单。浏览器验证两页的记录同时操作、
切换筛选后仍保留选择、取消确认不修改数据，以及单笔操作不清空无关选择。

阶段 7 的难点是“导出当前筛选”与“跨页勾选”可能指向不同范围，同时千分位金额中的
逗号会破坏未转义 CSV 的列数。解决方式是明确勾选优先，并通过查询服务统一获取最新数据，
在生成文件前校验全部状态；CSV 所有字段加双引号，内部双引号翻倍，保留换行、Unicode
和金额零值。用自动测试覆盖范围优先级、状态改变、特殊文本和公式前缀，再用 Python
标准 csv 模块独立解析生成文件，确认金额逗号不增加列数。
